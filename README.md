# つくばVPN

[![build](https://github.com/RTCK-reina/TsukubaVPN/actions/workflows/build.yml/badge.svg)](https://github.com/RTCK-reina/TsukubaVPN/actions/workflows/build.yml)

VPN Gate（筑波大学の学術実験プロジェクトが公開している公開VPN中継サーバー群）から
サーバーを選んで、ボタン1つで macOS を VPN 接続させるネイティブアプリ。

- 本体: `/Applications/つくばVPN.app`
- ソース: `~/Developer/TsukubaVPN`
- 実行時の作業フォルダ: `~/Library/TsukubaVPN`

## 使い方

1. アプリを開く（起動時に自動でサーバー一覧を取得する）
2. ① で国を選ぶ（台数と混み具合つき）
3. ② に「おすすめ」が自動で入る。変えたいときだけ「自分でえらぶ」
4. 下の大きい緑ボタン **「VPN につなぐ」** を押す
5. Mac のパスワードを入力する（**アプリを開いてから最初の1回だけ**）
6. ヘッダが緑になり、「いまの見た目のIP」が接続先の国のIPに変われば成功

切るときは同じボタン（赤の「VPN を切る」）。切ったあとつなぎ直しても、
サーバーを変えても、パスワードはもう聞かれない。アプリを終了すると裏の常駐も片付き、
次に開いたときにまた1回だけ聞かれる。

### 接続テスト（通信を切り替えずに動作確認する）

「くわしい設定」→ **「接続テスト（通信は切り替えません）」**。
`--route-nopull` でトンネルだけを張り、経路もDNSも変更せずに「utun が作れるか」だけを確認して即座に畳む。
リモート作業中・オンライン会議中でも安全に叩ける。結果は作られた仮想インターフェース名・
トンネル内部IP・デフォルト経路の前後比較つきで表示される。失敗時は最大5台まで自動で次を試す。

## 仕様

| 項目 | 内容 |
|---|---|
| サーバー一覧 | `https://www.vpngate.net/api/iphone/` |
| **一覧の自動更新** | 起動時／**接続直前**／**アプリが前面に戻ったとき**に、最終取得から10分以上経っていれば自動で取り直す。定期ポーリングはしない |
| 通信方式 | OpenVPN。UDP を優先し、UDP が無いサーバーでは TCP。`openvpn` は Homebrew 版 |
| **接続の仕組み** | **共通プロファイル1枚 + 管理インターフェース**。openvpn は一度だけ root で常駐起動し、接続先の指定・乗り換え・再試行・切断は管理コマンドで行う |
| 証明書検証 | 埋め込みCA（ISRG Root X1）＋ `remote-cert-tls server` でサーバー証明書の用途まで検証 |
| 設定の無害化 | APIから来た設定は許可リスト方式で再構成。想定外のディレクティブは一切通さない |
| 並び順 | 速度・応答・稼働日数・混雑度の合成スコア（★1〜5と「空いている/混雑」で表示） |
| 候補 | 5台。上位3台＋「空いている」2台。設定を組み立てられない候補はその1台だけ除外して続行 |
| 自動フォールバック | 20秒以内につながらなければ次の候補へ。常駐プロセスの中で順に試すので、何台目でもパスワードは増えない |
| 失敗の記憶 | 失敗したサーバーは10分間だけ後回し |
| 権限 | **openvpn を常駐させる最初の1回だけ**管理者権限。以後の接続・乗り換え・切断・完全終了はすべて権限不要 |
| 管理IF | 起動のたびに空きポートを実測して割り当て、インストール固有のランダムパスワードで保護。127.0.0.1 のみ |
| 排他 | `daemon.sh` は既に常駐していれば何もしない（二重起動しない） |
| **DNS** | サーバーがpushしたDNSへ切り替え、切断時に復元。**切り替えに失敗しても接続は落とさず**、アプリが黄色い警告で知らせる。復元に失敗した場合はバックアップを残して再試行できる |
| 全通信の経路 | サーバーが `redirect-gateway def1` を push するため、全トラフィックがトンネル経由 |

### DNS を「失敗しても接続は生かす」設計にした理由

OpenVPN は `--up` スクリプトが非ゼロ終了すると接続ごと中断する。
DNS切り替えの些細な失敗で5台全滅させてしまうと、原因がサーバー側に見えて診断できない。
そこで up.sh / down.sh は必ず 0 で終わり、結果を `dns-status.txt` に残す。
アプリはそれを読んで「つながっていますが、DNSは元のままです」と警告する。
リークに気づけるが、繋がらない事故は作らない。

### 内部の作り

- `Sources/VPNGateAPI.swift` — CSV取得とパース
- `Sources/VPNController.swift` — openvpn の常駐起動・監視、共通プロファイル生成、空きポート確保、設定の無害化
- `Sources/Management.swift` — 管理IFの生ソケットと接続セッション（接続・乗り換え・切断のすべて）
- `Sources/Scripts.swift` — root で走るシェル（daemon / stop / up / down / selftest）
- `Sources/AppModel.swift` — 状態管理・候補選択・一覧の鮮度管理・失敗の記憶
- `Sources/ContentView.swift` — UI

#### なぜプロファイルが1枚で足りるのか

VPN Gate が配る OpenVPN 設定は、**全サーバーで `<ca>` / `<cert>` / `<key>` /
cipher / auth が完全に同一**で、サーバーごとに違うのは `remote` と `proto` の2行だけ。
（`verify.sh` が毎回全台をデコードして一致を確認している。2026-08-08 時点で 98/98 台が一致）

そこで openvpn を共通プロファイル1枚で `--management-query-remote --management-hold` 付きで
常駐起動しておき、接続先は管理ソケットから `remote MOD <ip> <port>` で差し込む。
proto の違いは `<connection>` ブロックを udp / tcp の2つ置き、合わないほうに
`remote SKIP` を返すことで吸収する。

結果として、

- **接続** = `hold release` → 接続先を答える
- **別サーバーへ乗り換え** = `signal SIGUSR1` → 新しい接続先を答える（同じプロセスのまま）
- **候補フォールバック** = 20秒つながらなければ次の候補を答えるだけ
- **切断** = `signal SIGUSR1` して hold に戻す（down.sh が DNS を戻す。プロセスは待機で残る）
- **完全終了** = `signal SIGTERM`

がすべて一般ユーザー権限で完結する。root が要るのは openvpn を起動する `daemon.sh` だけ。
管理ソケットが受け付けるのは openvpn 自身の限られたコマンド語彙だけなので、
自前の特権ヘルパを置くより攻撃面が狭い。

管理ソケットが死んでいるときの保険として `stop.sh` を昇格実行する経路も残してある。

## ビルド / 検証

```sh
cd ~/Developer/TsukubaVPN
./build.sh         # build/つくばVPN.app を作る（ad-hoc署名まで）
./verify.sh        # 静的検証（API・無害化・スクリプト生成・構文・実サーバー疎通・DNSスクリプト）
./livetest.sh      # 統合検証。ルート権限なしで到達できる限界まで実サーバーで通す（65項目）
./livetest.sh KR   # 国コード指定。日本が不調なときの切り分け用
```

`livetest.sh` は `dev null` で「utun を作る工程だけ」を回避し、本番と同一のシェル・
同一のアプリコード（`VPNSession`）を実サーバーに対して走らせる。`networksetup` はモックに
差し替わるので、実機の DNS 設定には触れない。

常駐起動 → 死んだ候補からの自動フォールバック → TLS確立 → PUSH_REPLY → up スクリプトでの DNS 切替 →
**別サーバーへの乗り換え（同一プロセスであることをPIDで確認）** → 切断と DNS 復元 →
**待機状態からの再接続** → アプリ再起動相当の再アタッチ → 全候補失敗時の `exhausted` →
完全終了 → `stop.sh` による強制停止 まで通す。

## 既知の性質

- **公開サーバーは頻繁に落ちている。** 上位3台が同時に死んでいて4台目で成功、は普通に起きる。
  候補5台とフォールバックはそのための設計で、「1台目で失敗」はバグではない。
- 短時間に何十回も接続すると VPN Gate 側に `auth-failure` で断られる。
  実測では日本のサーバーに約100回接続した直後、日本だけ全滅し韓国は正常だった
  （アプリを介さない素の openvpn でも同じ）。日本が駄目なときは国を変えて切り分けるのが早い。

## 注意

- VPN Gate はボランティア提供の公開サーバー。**通信内容は運営者に記録され得る**。
  ログイン、決済、業務通信には使わないこと。
- データ通信の暗号は AES-128-CBC + SHA1（VPN Gate 側の仕様）。秘匿ではなく経路変更のための道具。
- DNS が VPN 用のまま残った場合は、アプリの黄色い警告か「くわしい設定 → DNS設定を元に戻す」から復元できる。

## 接続テストの記録（Claude を落としている間の記録用）

Claude / Cowork を終了した状態で本接続を試すとき、その間の出来事を丸ごと残すためのブラックボックス。
Terminal 上で独立して動くので、Claude を落としても記録は続く。

1. **`記録開始.command`** をダブルクリック
2. Claude / Cowork を終了してよい
3. つくばVPN.app で「VPN につなぐ」→ つながったら30秒ほど通信を試す →「VPN を切る」
4. **`記録停止.command`** をダブルクリック（Finder に `report.md` が出る）
5. Claude に「ログ見て」と言えば読み取れる

3秒おきに以下を記録し、変化があった瞬間だけを `events.log` に抜き出す。

- デフォルト経路 / utun の一覧とトンネル内部IP
- 全ネットワークサービスの DNS 設定
- openvpn のプロセス、`result.txt` / `attempt.txt` / `dns-status.txt`
- **グローバルIP**（`https://1.1.1.1/cdn-cgi/trace` を使うので DNS が壊れていても取れる）
- **名前解決の可否**（名前でのアクセスが通るか）
- openvpn のログ（`try*.log` を消される前に退避）

`report.md` には「トンネルができたか／経路が切り替わったか／IPが変わったか／DNSが切り替わったか／
後片付けできたか」を ✅❌ で判定して出す。生データは `raw.tsv`。止め忘れても3時間で自動終了する。

```sh
./record.sh start | stop | status   # コマンドで直接使う場合
```

## 未検証

- 長時間接続したままのスリープ復帰。
- 目視でのUI確認。画面収録権限がないため、アクセシビリティツリーでの要素確認までしか行っていない。

## 開発の進めかた

`main` は保護されています。直接 push はできません。

```sh
git switch -c fix/なにか
# 直して
./build.sh && ./verify.sh && ./livetest.sh
git commit -am "..."
git push -u origin fix/なにか
gh pr create --fill && gh pr merge --squash --delete-branch
```

PR には CI（macOS ランナーでのビルド・バンドル検査・シェルテンプレートの構文検査）が走り、
これが通らないとマージできません。承認者は不要（approvals = 0）です。

CI では `verify.sh` / `livetest.sh` を回していません。これらは VPN Gate に実接続するため、
CI の IP から自動で叩き続けるのは学術実験プロジェクトへの迷惑になるからです。
接続経路に触る変更をしたときは、手元で `./livetest.sh` と `./record.sh` を回してください。

緊急時に保護を一時解除する場合は Settings → Branches → main の Edit から。
